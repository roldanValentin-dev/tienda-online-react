## 🔐 AUTENTICACIÓN

### 1. Registro de Cliente
**Endpoint:** `POST /api/auth/register-cliente`  
**Autenticación:** ❌ No requiere  
**Rol:** Público  
**Descripción:** Registra un nuevo cliente en la tienda online

**Request Body:**
```json
{
  "nombre": "Juan",
  "apellido": "Pérez",
  "email": "juan.perez@email.com",
  "password": "Password123!",
  "telefono": "+54 11 1234-5678",
  "direccion": "Av. Siempre Viva 123, CABA"
}
```

**Response 200:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "base64_encoded_refresh_token",
  "email": "juan.perez@email.com",
  "firstName": "Juan",
  "lastName": "Pérez",
  "roles": ["Cliente"],
  "expiresAt": "2024-01-01T13:00:00Z"
}
```

**Validaciones:**
- Email: formato válido, máximo 100 caracteres
- Nombre: requerido, máximo 50 caracteres
- Apellido: requerido, máximo 50 caracteres
- Teléfono: formato válido (regex), 8-20 caracteres
- Dirección: requerida, máximo 200 caracteres
- Password: mínimo 6 caracteres, 1 mayúscula, 1 minúscula, 1 número

### 2. Login
**Endpoint:** `POST /api/auth/login`  
**Autenticación:** ❌ No requiere  
**Rol:** Público  
**Descripción:** Inicia sesión con email y contraseña

**Request Body:**
```json
{
  "email": "juan.perez@email.com",
  "password": "Password123!"
}
```

**Response 200:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "base64_encoded_refresh_token",
  "email": "juan.perez@email.com",
  "firstName": "Juan",
  "lastName": "Pérez",
  "roles": ["Cliente"],
  "expiresAt": "2024-01-01T13:00:00Z"
}
```

**Errores:**
- 401: Email o contraseña incorrectos
- 429: Demasiados intentos (rate limiting)

---

### 3. Renovar Token
**Endpoint:** `POST /api/auth/refresh`  
**Autenticación:** ❌ No requiere  
**Rol:** Público  
**Descripción:** Renueva el access token usando el refresh token

**Request Body:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "base64_encoded_refresh_token"
}
```

**Response 200:**
```json
{
  "token": "nuevo_access_token",
  "refreshToken": "nuevo_refresh_token",
  "email": "juan.perez@email.com",
  "firstName": "Juan",
  "lastName": "Pérez",
  "roles": ["Cliente"],
  "expiresAt": "2024-01-01T14:00:00Z"
}
```

**Errores:**
- 401: Token inválido o expirado

---

### 4. Cerrar Sesión (Revocar Token)
**Endpoint:** `POST /api/auth/revoke`  
**Autenticación:** ✅ Requiere Bearer Token  
**Rol:** Cliente (autenticado)  
**Descripción:** Revoca el refresh token actual (cierra sesión en todos los dispositivos)

**Headers:**
```
Authorization: Bearer {token}
```

**Response 200:**
```json
{
  "message": "Token revocado exitosamente"
}
```

  "detalles": [
    {
      "id": 1,
      "productoId": 1,
      "productoNombre": "Torta de Chocolate",
      "productoImagen": "/images/productos/torta-chocolate.jpg",
      "productoCategoria": "Tortas",
      "cantidad": 2,
      "precioUnitario": 5500.00,

### 15. Cancelar Pedido
**Endpoint:** `PUT /api/pedidos/{id}/cancelar`  
**Autenticación:** ✅ Requiere Bearer Token  
**Rol:** Cliente  
**Descripción:** Cancela un pedido (solo si está en estado Pendiente)

**Headers:**
```
Authorization: Bearer {token}
```

**Parámetros:**
- `id` (path): ID del pedido

**Response 200:**
```json
{
  "id": 1,
  "clienteOnlineId": 1,
  "clienteNombre": "Juan",
  "clienteEmail": "juan.perez@email.com",
  "fechaPedido": "2024-01-10T15:30:00Z",
  "fechaEntrega": "2024-01-15T10:00:00Z",
  "estado": "Cancelado",
  "estadoId": 6,
  "total": 17000.00,
  "observaciones": "Por favor, entregar antes de las 10 AM",
  "detalles": []
}
```

**Lógica:**
- Solo se puede cancelar si el estado es "Pendiente"
- Si el stock fue descontado, se restaura automáticamente
- Se registra la fecha de cancelación

**Errores:**
- 401: No autenticado
- 403: No tiene permiso para cancelar este pedido
- 400: No se puede cancelar un pedido en este estado
- 404: Pedido no encontrado

### 17. Subir Imagen de Producto (Admin)
**Endpoint:** `POST /api/productos/{productoId}/imagenes`  
**Autenticación:** ✅ Requiere Bearer Token  
**Rol:** Admin/Vendedor  
**Descripción:** Sube una nueva imagen para un producto

**Headers:**
```
Authorization: Bearer {token}
Content-Type: multipart/form-data
```

**Parámetros:**
- `productoId` (path): ID del producto

**Form Data:**
- `file` (file): Archivo de imagen (JPG, JPEG, PNG, GIF, WEBP)
- `orden` (int, opcional): Orden de visualización (default: 0)
- `esPrincipal` (bool, opcional): Si es la imagen principal (default: false)

**Validaciones:**
- Tamaño máximo: 5 MB
- Formatos permitidos: .jpg, .jpeg, .png, .gif, .webp
- Archivo requerido

**Response 201:**
```json
{
  "id": 4,
  "productoId": 1,
  "url": "/images/productos/20240501_abc123.jpg",
  "orden": 3,
  "esPrincipal": false
}
```

**Errores:**
- 400: Archivo inválido o no proporcionado
- 401: No autenticado
- 404: Producto no encontrado

**Ejemplo con cURL:**
```bash
curl -X POST http://localhost:7097/api/productos/1/imagenes \
  -H "Authorization: Bearer {token}" \
  -F "file=@/path/to/image.jpg" \
  -F "orden=0" \
  -F "esPrincipal=true"
```

**Ejemplo con JavaScript (FormData):**
```javascript
const formData = new FormData();
formData.append('file', fileInput.files[0]);
formData.append('orden', 0);
formData.append('esPrincipal', true);

fetch(`/api/productos/${productoId}/imagenes`, {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${token}`
  },
  body: formData
});
```

## 🔒 AUTENTICACIÓN Y AUTORIZACIÓN

### Headers Requeridos
Para endpoints que requieren autenticación:
```
Authorization: Bearer {access_token}
```

### Flujo de Autenticación
1. Cliente se registra: `POST /api/auth/register-cliente`
2. Recibe `token` y `refreshToken`
3. Usa `token` en header `Authorization` para requests autenticados
4. Cuando `token` expira (1 hora), usa `refreshToken` para renovar: `POST /api/auth/refresh`
5. Al cerrar sesión: `POST /api/auth/revoke`

### Manejo de Errores de Autenticación
- **401 Unauthorized**: Token inválido, expirado o no proporcionado
- **403 Forbidden**: Token válido pero sin permisos para la acción

---

## 📝 CÓDIGOS DE RESPUESTA HTTP

| Código | Significado | Cuándo se usa |
|--------|-------------|---------------|
| 200 | OK | Operación exitosa |
| 201 | Created | Recurso creado exitosamente |
| 204 | No Content | Operación exitosa sin contenido |
| 400 | Bad Request | Datos inválidos o error de validación |
| 401 | Unauthorized | No autenticado o token inválido |
| 403 | Forbidden | Sin permisos para la acción |
| 404 | Not Found | Recurso no encontrado |
| 429 | Too Many Requests | Rate limiting excedido |
| 500 | Internal Server Error | Error del servidor |
